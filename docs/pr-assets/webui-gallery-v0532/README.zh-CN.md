# 在 DSH 0.2.1 上采集的 v0.5.32 WebUI 图集

[English](./README.md)

记录于 2026-10-17（Asia/Shanghai）。文档使用的图集 [webui-v0.5.19](../../assets/webui-v0.5.19/README.md) 于 2026-09-28 在 DSH 0.1.7-rc.2 上采集，而 dsh-mnemon 已不再支持这个版本；DSH 0.2 也改变了插件周围的界面：侧边栏、插件页与可组合记忆的页面。本次改动在 DSH 0.2.1-rc.2 上由真实的 DeepSeek 模型作答，重新采集同样的流程，得到 [webui-v0.5.32](../../assets/webui-v0.5.32/README.md)（以将发布它的版本命名），并让当前文档改用它。发布说明与 PR 记录仍链接 v0.5.19 图集，它作为带日期的记录保留。代码没有改动；changeset 针对随 `dsh-mnemon` 一起发布到 npm 的两份 README。

## 图集内容

- 每种语言五段录制（召回、存入、纠正、记忆系统、插件），均为 MP4，其中四段另有 GIF；以及 28 张截图：25 张桌面、3 张窄屏。共 74 个文件、23.8 MB，v0.5.19 为 68 个文件、17.7 MB。
- 流程与截图名称沿用 v0.5.19，因此链接只需改目录。新增三张截图：`chat-save-target`，即“保存到”菜单；`plugins-list`，即 DSH 的插件页，以 1280 × 858 截取，页面标题与可组合记忆一行都完整可见；`memory-runtime-limits`，即运行时记忆页面顶部的容量卡片，现由配置参考使用。这张截图在同一构建的全新夹具上、对话开始前截取，manifest 对此有标注；指南仍使用从回合打开的 `memory-runtime`。存入记忆的录制多了第四段，用于展示“保存到”菜单。
- [图集 README](../../assets/webui-v0.5.32/README.md#what-changed-since-v0519--与-v0519-相比的变化) 列出与 v0.5.19 相比的变化；manifest 记录了每个文件的视口、大小、时长与 SHA-256，以及每一轮读到和写入的内容。

## 采集方式

- 代码修订 `64933532`：本分支合入 `origin/main`（`1fd64eaf`）后的提交，以 Node 24.19.0 与 pnpm 10.13.1 构建，由固定的 DSH 0.2.1-rc.2 提供 WebUI，Mnemon CLI 0.2.10，通过 DevTools 协议驱动的无头 Chrome 155 以 1280 × 800 与 390 × 844、2 倍像素、浅色界面采集。本分支之后又合入了 `origin/main`（`03dd40a4`，#423），这些内部整理不改变用户所见的任何内容。
- 每种语言在全新的 `node scripts/serve-e2e.mjs --docs-demo --live-model`（英文为 `--docs-demo=en`）上完整走一遍。DeepSeek 密钥只通过该进程的环境变量传入，不出现在任何文件、日志或图像中。采集期间没有运行嵌入服务：Mnemon Native 嵌入设置保持默认，dsh-mnemon 不提供覆盖设置，Mnemon 尝试自己的默认地址而没有服务响应。因此每次存入记忆空间都会提示这条记忆没有向量；图集 README 写明了这一点。
- 驱动 WebUI、录制屏幕与组装图集的脚本与 v0.5.19 一样不放进仓库。截图沿用 v0.5.19 的 JPEG 质量（相同的量化表），MP4 为 CRF 27，GIF 为 880 像素、8 fps，每个 GIF 使用一套 256 色调色板；画面中出现的唯一路径是夹具的临时目录。

## 取舍

每条回复、存入记忆的候选内容与回执、每个 Agent 回答都逐一读过，每段录制都抽帧检查。英文采用第一遍。中文在同一构建上、用同一个问题共走了七遍。前五遍里，Agent 查询拿到的都是提到 ClickHouse 的五条记忆中的四条，相关度都是 0.58，不含 9 月 12 日的事故，因此回答说证据中没有事故记录；在其中一遍的夹具上，随后用同一问题直接检索，返回的是另外四条，再做一次 Agent 查询就引用了这次事故，可见一次召回返回哪四条，每次调用都可能不同。最终采用第六遍：它是第一遍 Agent 回答引用了这次事故（四条记忆之一）、其余各轮也与第一遍同样合格的采集。它的第一个回答读了两份项目档案，没有召回记忆空间，因此中文的召回录制与回合记忆栏只显示档案，中文替代文本也如此描述。第七遍同样引用了这次事故，第一轮同样只读了档案。

在此修订之前的试采集发现了录制工具的两个问题，都已在这几遍之前修好：拼接录制片段时，片段末尾的静止画面（例如存入记忆的回执）会被截掉；每段 MP4 都比最后一帧多出 1.6 秒。

## 采集中发现的问题

三个会改变用户所见内容的行为作为第 12 至 14 项加入[计划](../../plans/review-gaps-2026-10.md)（英文），并加入中英文[路线图](../../zh-CN/roadmap.md#下一步2026-年-10-月审查发现的问题)：

- 嵌入设置保持默认且没有嵌入服务时，每次存入记忆空间的回执都写着“嵌入没有成功”，在默认安装上读起来像失败；
- 被替换的运行时记忆条目显示创建时间，从不显示更新时间（`plugins/dsh-mnemon-source-runtime/src/client/pages.tsx:114` 与 `:131`）；
- 在 390 像素宽度下，英文界面中当前的记忆系统标签可能位于屏幕之外，回合记忆栏的摘要和记忆空间卡片的计数会被截断。

对本次改动的审阅又在录制与截图中发现四个问题，逐一对照代码核实后，以同样方式列为第 15 至 18 项：

- 空间状态仍在检测时，记忆空间概览中的卡片显示 0 条记忆、0 条连接和 0 B（中文记忆系统录制，9.9 秒）；
- 从回合打开的页面在记忆系统的 Source 目录返回之前只有“状态”标签和一块空白画布，本次录制中持续一到两帧（中文召回录制 10.0 秒，英文 13.5 秒）；
- 图谱最多绘制 24 个实体，页脚也只计入这些实体，因此存入的记忆带来新实体后，实体页面显示 26 个，页脚显示 24 个；在刚预置的演示数据上两者都是 22；
- 节点较多时，图谱标签相互重叠并越过右侧边缘（“Code re”，以及压在“A PR needs at leas…”上的“No production depl…”）。

另外观察到、但未列入计划的：上文 Agent 查询每次拿到的证据不同；Mnemon CLI 自动提取的实体，例如“2.4”“2.9”“SDK”以及来自 Next.js 的“Next”，出现在实体列表与图谱中；任务 Agent 保留已被取代的记忆，并把新记忆与它关联，这是有意的设计（#148）；以及中文回复进行中，模型的思考行会短暂以英文显示。

## 审阅之后
