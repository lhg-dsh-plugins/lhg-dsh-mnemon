# 一次扫描读取 Hindsight 实体名称

[English](./README.md) | [验证记录](./verification.json)

这个问题是在检查记忆空间各 Provider 如何解析服务端数据时发现的。Hindsight 服务端可能把一条记忆的实体放在一个字符串里发来，例如 `Alice (person), TypeScript (language)`。驱动用 `/\s*\([^)]*\)\s*$/u` 去掉每个名称末尾括号里的注释。

如果名称由大量 `(` 组成且没有 `)`，这个正则会从每个 `(` 开始一直扫描到字符串末尾，耗时随名称长度的平方增长。检索、浏览和图谱都会读取实体；正则运行期间，Host 不能处理任何其他事情。

基线：main `20e4ab67`。修复：`ebfa0cb2`。运行于 2026-10-13（Asia/Shanghai），macOS 15.6 arm64，Node 24.19.0。

## 修复

注释改为一次扫描找出：
1. 找到名称末尾的 `)`；
2. 找到它前面的那个 `)`；
3. 取这两个 `)` 之间最靠左的 `(`。

这个 `(` 之前的部分，就是去掉注释后的名称。末尾不是 `)` 的名称只去掉首尾空白，和以前一样。

## 结果一致

[`harness/note-equivalence.mjs`](./harness/note-equivalence.mjs) 比较旧正则和新写法。它在所有由 `(`、`)`、空格、制表符和一个字母组成、长度不超过 10 的字符串上分别运行两者，共 12,207,031 个字符串，结果没有任何不同。

## 耗时

同一脚本还对「`x` 后接大量 `(`」的名称计时：

| 名称中 `(` 的数量 | 旧正则 | 新写法 |
|---:|---:|---:|
| 10,000 | 40 ms | 低于 0.01 ms |
| 20,000 | 194 ms | 低于 0.01 ms |
| 40,000 | 706 ms | 低于 0.01 ms |
| 80,000 | 2,617 ms | 低于 0.01 ms |

名称长度每翻一倍，旧正则的耗时大约变为四倍。之前在机器忙于其他任务时测的一次，80,000 个时耗时 4.5 秒。

## 自动检查

`plugins/dsh-mnemon-provider-hindsight/tests/driver.spec.ts` 新增测试 “reads entity names without their notes, and a name of many "(" at once”。它读取带注释和不带注释的普通名称；还读取一个含 120,000 个 `(` 的名称，并在测试时限内完成，而 main 做不到。

## 限制

- 没有运行 Hindsight 服务端。实体字符串来自服务端，所以上面的耗时，就是一个恶意或损坏的实体名称能让 Host 停顿的时间。
- 注释本身含有 `)` 的名称（例如 `Name (a) b)`），旧正则从来不会去掉它的注释；新写法也同样保留。
