# 在 DSH 0.2.1 的桌面版中从 0.5.30 及更早版本更新

[English](README.md) | [验证记录](validation.json)

验证于 2026-10-19（Asia/Shanghai），对应 [#433](https://github.com/omdsh-dev/dsh-mnemon/issues/433) 与 [#436](https://github.com/omdsh-dev/dsh-mnemon/issues/436)。

## 缺口

两份报告都来自 DSH 0.2.1-rc.2 的桌面版，装的 dsh-mnemon 都不支持 DSH 0.2.1：#433 是 0.5.29（记忆子 Agent 失败），#436 是 0.5.27（声明了宿主不安装的 peer）。0.5.31 已修复这两个问题，所以办法是更新，但文档没有说清怎么更新：

- 在 DSH 0.2.1 上，dsh-mnemon 0.5.30 及更早版本的**检查版本 → 更新**会停在 `already-installed`，因为 DSH 不再覆盖安装 profile 中已有的插件。
- 文档为这种情况给出的是 `dsh plugin --profile web add dsh-mnemon@<版本>`，但命令行不管理桌面版的 `desktop` profile；另有两处仍让读者去运行“命令”或“在命令行中”更新。
- 在插件页卸载 dsh-mnemon 后重新添加，文档只写给了 0.5.21 及更早的版本。DSH 0.2.1 的插件页对它安装的插件也给出同样的建议：“该插件已安装。如需升级，请卸载后重新安装”。
- 有两处说升级后的 DSH 会停用不受支持的版本。DSH 0.2 会这样处理 0.5.19 之前的版本；在 DSH 0.2.1 上，0.5.19 至 0.5.30 仍会运行（两份报告和下面的运行都是如此），只是记忆子 Agent 与检查版本会失败。

## 改动

只改文档，中英文同步：

- 安装与启动：
  - “桌面版”：DSH 0.2.1 上的 0.5.30 及更早版本与 0.5.21 及更早版本一样，更新一次即可：在插件页卸载 dsh-mnemon，再通过**添加插件**重新安装，输入带版本号的名称，例如 `dsh-mnemon@0.5.32`。
  - “更新与卸载”：`already-installed` 那一条同时给出两种方法。网页先退出 DSH，运行命令，再启动 DSH；桌面版卸载后重新添加。
  - “常见问题”：新版本发布后的 24 小时内，DSH 0.2.1 会说明添加插件实际装上的版本，DSH 0.2.0 则不会。
  - “升级 DSH”：说明升级后的 DSH 如何对待较早的版本，并改为指向更新步骤，而不是“要运行的命令”。
- 兼容性：
  - “升级顺序”：说明 DSH 0.2 与 0.2.1 如何对待较早的版本，并在命令行方法旁写明桌面版的方法。
  - “DSH 0.2.0 与 0.2.1”：`already-installed` 的说明改为指向升级顺序，而不是命令行。
- 运维：
  - “版本检查与更新”：说明 DSH 0.2.1 为什么会停在这里，以及桌面版卸载后重新添加。
  - 故障排查：0.5.18 那一行改为卸载后重新添加，而不是在插件页更新，因为插件页不能更新插件。
- v0.5.32 发布说明：关于桌面版的那句给出带确切版本号的方法，并放在说明为何要写明版本的那句之后。

## 验证

每次运行都使用未经修改的 npm DSH 0.2.1-rc.2（npm `latest` 与 `next`），全新的 home、DSH home 与 pnpm store，以及真实的 npm registry。网页 profile 代替桌面版的 `desktop` profile：两者使用同一个 DSH 插件页和安装器。

1. 启动 WebUI 前先安装较早的版本：0.5.29、0.5.27，以及带有已保存设置的 0.5.29。这个设置是把 USER.md 上限设为 6000 字节，保存在 DSH 保存插件设置的位置，即 profile 的 patch 层。状态页显示该版本、系统正常，并在页面上添加一条运行时记忆。
2. 在插件页打开 dsh-mnemon，点击**卸载**：[0.5.29 的详情页](detail-0.5.29.jpg)。DSH 请求确认（“卸载「可组合记忆 (dsh-mnemon)」？ 卸载后它提供的功能会消失。”），随后移除插件，侧边栏中的记忆系统随之消失。
3. **添加插件**装上了 0.5.32（[安装结果](added-0.5.32.jpg)），点击**立即启用**后立即显示 0.5.32、系统正常。
   - 前两次只输入了 `dsh-mnemon`。该版本已发布 43 小时，超过 pnpm 24 小时的最短发布时间。
   - 第三次输入了 `dsh-mnemon@0.5.32`，profile 中记录的就是这个确切版本。
4. 重启后，状态页显示 **dsh-mnemon 0.5.32 / 系统正常**（[状态页](status-after-restart.jpg)）。
   - 卸载前写入的运行时记忆仍在（[运行时记忆](runtime-kept.jpg)）。
   - 第三次运行中，USER.md 上限仍显示 5.9 KB，设置也仍在 patch 层中。
   - 检查版本显示 0.5.32 已是最新。Profile 中 17 个组件均为 Starter 锁定的版本，重启时没有激活警告。

三次运行的每一步都通过，没有控制台错误；[validation.json](validation.json) 记录了每项结果。

## 限制

- 没有运行桌面版本身；它的插件页与安装器和网页 profile 一样来自 DSH。
- 新版本发布后的 24 小时内，不写版本号的添加插件会装上一个较早的版本，它可能仍会停在 `already-installed`。因此文档要求写明版本号。
