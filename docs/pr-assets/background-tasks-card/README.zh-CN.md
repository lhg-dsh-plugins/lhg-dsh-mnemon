# 可跟随会话的任务 Agent — PR #354

[English](./README.md) | [验证记录](./verification.json)

PR #354 让存入记忆、Agent 查询、整理与归档背后的任务 Agent 使用发起该工作的会话的模型。最初提交的版本有三个问题：
- 改变了所有 Profile 中 `taskAgentModel: inherit` 的含义；
- 发起的会话没有打开时，会转而使用另一个已打开会话的模型；
- 在记忆系统状态页上为这个设置加了第二个编辑入口。

维护者的调整保留作者的提交与这项功能，把它作为三个选项之一，放在这个设置原本所在的页面。状态页与 main 相同。

## DSH 如何处理模型选择

两个宿主上，DSH 对模型选择都有两种处理：
- 在某个会话中选择的模型，会用于该会话的下一次请求。DSH 同时把它保存为新会话默认模型（会话控制器中的 `agentDefaultModel.saveSelection`）。任务 Agent 以往使用这个默认模型，因此运行在最近一次在任意会话中选择的模型上。
- 委派出去的子 Agent 沿用父 Agent 的路由：父 Agent 最近一次请求的 provider、模型与推理等级，第一次请求之前则用创建时的路由。因此空闲审查以及会话发起的其他委派，始终跟随该会话。

所以多数情况下，任务 Agent 本来就运行在其会话的模型上。两者不一致的情形是：之后另一个会话选择了不同的模型，例如一个会话用快速模型、另一个用更强的模型。此时在第一个会话中存入记忆，会运行在第二个会话的模型上，而第一个会话的审查仍使用第一个会话的模型。

## 改动

**任务 Agent 模型**位于“插件 → 可组合记忆 → 分层策略 → **后台任务**”，现在是三个选项之一：

| 选项 | 任务 Agent 使用的模型 | 保存为 |
|---|---|---|
| **跟随全局**，默认（原**跟随主链路**） | DSH 保存的新会话模型，与以前相同 | `{ mode: inherit }` |
| **跟随会话**（新增） | 发起任务的会话所用的模型，与其审查一致，前提是该会话处于打开状态；否则跟随全局 | `{ mode: inherit, followConversation: true }` |
| **自定义**（原**指定模型**） | 单独指定的 Provider 与模型 | `{ mode: fixed, provider, model }` |

- **跟随会话使用的路由**，就是 DSH 给该会话自身委派所用的路由：其最近一次请求的模型与推理等级，第一次请求之前则用创建时的路由。
- **只认发起任务的那个会话。**最初的版本会转而使用恰好处于打开状态的其他会话。
- **降级后照常工作。**跟随会话是继承路由上的一个配置键，而不是单独的模式。v0.5.30 的 schema 会保留不认识的键，其解析器仍按 `inherit` 读取，因此降级后的 Host 会跟随全局；未知的模式则会导致加载失败。
- **页面说明实际路由。**页面实时读取已保存的选项，在别处所做的选择会立即显示；“当前将使用”一行会注明来源：**新会话模型**、**当前会话**或**自定义**。
- **保留作者对对话框的修复：**在对话框上方打开的菜单自行处理 Esc 与 Tab。

最初版本自己的截图展示了它放在状态页上的编辑器：[卡片](./status-background-tasks-zh.png)、[指定模型](./status-background-tasks-fixed-model-zh.png)与[其 Provider 列表](./status-background-tasks-provider-zh.png)。第一次调整在那里保留了说明路由的一行与齿轮；由于这个设置本来就在分层策略页面，这部分也已去掉。

对第一次调整的独立审查指出了页面还需要的处理，现在每一项都在分层策略页面有测试：
- 放弃尚未写入的自定义模型时，应保留原来的选项；
- 自定义路由时，**重新读取**应读取完整的模型目录；
- 没有 DSH 默认模型时，或页面尚未读到设置时，显示的路由应与 Host 一致；
- 路由应带上会话的推理等级。

## 运行过程

两个宿主上运行相同的步骤。本地回环的模型替身 [harness/stub.mjs](./harness/stub.mjs) 记录每个请求指定的模型。它就是夹具自带的替身加上存入记忆的脚本，通过 `--live-model` 与测试密钥接入。

1. 会话 A 选择 DeepSeek-V4-Pro，得到一条回复。
2. 新建会话 B，选择 DeepSeek-V4.1-Flash，得到一条回复。
3. 回到 A，对其回复执行**存入记忆 → 交给任务 Agent**。
4. 打开“插件 → 可组合记忆 → 分层策略”查看选项。在本分支上选择**跟随会话**，A 再得到一条回复并第二次存入记忆。

| | A 的回复 | B 的回复 | A 存入记忆的任务 |
|---|---|---|---|
| main，DSH 0.2.0-rc.2 | `deepseek-v4-pro` | `deepseek-flash` | `deepseek-flash` |
| 本分支，**跟随全局**，两个宿主 | `deepseek-v4-pro` | `deepseek-flash` | `deepseek-flash` |
| 本分支，**跟随会话**，两个宿主 | `deepseek-v4-pro` | | `deepseek-v4-pro` |

跟随全局时，本分支与 main 相同：A 的任务运行在 B 的模型上，即 DSH 默认模型。跟随会话时，任务运行在 A 自己的模型上。该选项保存为 `taskAgentModel: { mode: inherit, followConversation: true }`。所有步骤都没有浏览器控制台错误。

## 测试

- **Host：**
  - 继承的路由除非跟随会话，否则保持 DSH 的新会话模型。
  - 跟随会话时，运行时维护和从该会话发起的页面任务都使用它的路由，推理等级也在内；尚未运行过的会话与 DSH 的委派一样使用创建时的路由。
  - 会话未打开、调用方没有会话，或请求头只有一半时，保持默认模型。
  - 无论选项如何，模型目录都会报告会话的路由与继承的路由。
- **配置：**该配置键未设置时关闭，对自定义路由不起作用，并且必须是布尔值。
- **分层策略页面：**
  - 带着自己的会话发起请求，只在选择跟随会话后才跟随它，在别处保存的选项会立即显示。
  - 放弃自定义模型时保留原来的选项；自定义路由时，**重新读取**会读取完整目录。
  - 没有 DSH 默认模型时，以及读到设置之前，显示的路由都正确。
  - 原有用例改用新的选项名称。
- **在最初的版本（`1fb83599`）上，其中 13 项失败：**8 项因其检查的内容而失败；另外 5 项失败只是因为选项改了名（3 项），或模型目录现在还会报告继承的路由（2 项）。例如，从未打开的会话发起的任务拿到了已打开会话的 `ai / space-bunny`。
