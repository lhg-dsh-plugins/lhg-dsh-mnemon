# 接入嵌入服务后重新采集的 v0.5.32 WebUI 图集

[English](./README.md)

记录于 2026-10-18（Asia/Shanghai）。[v0.5.32 图集](../../assets/webui-v0.5.32/README.md)的[第一次采集](../webui-gallery-v0532/README.zh-CN.md)时没有嵌入服务，每次存入记忆空间的回执末尾都有“未生成向量”，文档也就不得不解释一行装有本机 Ollama 的默认安装根本不会出现的提示。维护者决定接入真实的嵌入服务重新采集，让存入走正常路径并生成向量。本次改动按原文件名替换素材，重新生成 manifest 与图集 README，并更新描述第一次采集的语句与替代文本。代码没有改动；图集的 changeset 现在也写明了嵌入服务。

## 嵌入设置

- 官方 Ollama 0.40.6 CLI 在 127.0.0.1:11434（Mnemon 的默认地址）上提供 `nomic-embed-text`（768 维），即 Mnemon CLI 0.2.10 的默认嵌入模型。
- Mnemon Native 嵌入设置保持默认，**由 DSH 管理嵌入配置**为关闭，因此 DSH 不提供覆盖，Mnemon 使用的正是这个地址与模型，与装有本机 Ollama 的默认安装相同。夹具本身也没有设置嵌入。
- 每一遍结束后，`mnemon embed --status` 显示夹具的三个 Store 覆盖率均为 100%，包括存入的记忆。中文夹具在预置完成后也检查过一次，结果相同。两遍中没有任何回执带有向量提示。

## 采集方式

- 采集所用代码修订为 `bd70979f`（`main`，含 #424 至 #426），以 Node 24.19.0 与 pnpm 10.13.1 构建，由固定的 DSH 0.2.1-rc.2 提供 WebUI，Mnemon CLI 0.2.10，通过无头 Chrome 155 以 1280 × 800 与 390 × 844、2 倍像素、浅色界面采集。之后本分支合入了 `main` 的 `6724ccde`（#427）。这一改动只改写未生成向量时回执中的那一行，而这里的画面都不会出现那一行，因此采集结果依然有效。
- 问题与工具都与第一次采集相同：每种语言在全新的 `--docs-demo --live-model` 夹具上完整走一遍，DeepSeek 密钥只存在于夹具进程的环境中。`memory-runtime-limits` 在同一构建的全新夹具上、对话开始前截取，`plugins-list` 以 1280 × 858 截取。
- 工具有一处改动。图谱截图改为对齐吸顶页头的下沿取景，原先用的是固定偏移；这样两种语言中图谱自己的标题行都不会露出（第一次采集的中文 `memory-graph` 中它被遮去一半）。中文这一遍在改动之前完成，因此它的 `memory-graph` 在那一遍自己的夹具上、采集结束后随即重拍，数据相同，manifest 对此有标注。
