# v0.5.33：Git 同步能找到它的令牌，记忆任务不再留下空会话

**简体中文** | [English](../../en/releases/v0.5.33.md)

本补丁版本修复两个报告的问题，并写明桌面版如何从较早的版本更新：[#437](https://github.com/omdsh-dev/dsh-mnemon/pull/437) 至 [#441](https://github.com/omdsh-dev/dsh-mnemon/pull/441)。只有 Starter 有改动。

- **无论 Git 怎样配置，Git 同步都能找到它的令牌**（#441，issue #408）。电脑上的 Git 配置为主机指定了用户名，或开启了 `credential.useHttpPath` 时（Git Credential Manager 的设置就是这样），通过 HTTPS 的 Git 同步会一直提示「需要凭据」，尽管你已经登录或填写了令牌：Git 按那个用户名或路径去查令牌，什么也查不到。现在无论配置如何，Git 都按 dsh-mnemon 存入的用户名查找；主机名大写或带端口的地址（例如 `https://GitHub.com:443/...`）也能找到令牌。
  - gitee.com 不接受 `x-access-token`，因此改用 `oauth2` 提供令牌；其余主机仍用 `x-access-token`。
  - 需要其他用户名的主机（如 Bitbucket 或自建 Gitee）可在地址中写明用户名，例如 `https://x-token-auth@bitbucket.org/...`。地址中的密码或令牌仍会被拒绝。
  - 主机拒绝了已提供的凭据时，同步设置会说明这一点，并指出被拒的是哪一个：GitHub 登录、保存的令牌或 `MNEMON_SYNC_GIT_TOKEN`，而不再提示需要凭据。
- **记忆任务不再留下空会话**（#438，issue #435）。所有在对话之外运行的记忆任务都在一个任务 Agent 下运行，DSH 会保存它的会话：存入记忆、Agent 查询、项目档案归档、新记忆空间选择 Provider、整理名称与说明、运行时记忆容量维护以及记忆整理。DSH 没有这类会话的记录时，侧边栏会在**未分组**下把它列为一个空的**未命名**会话，每个任务新增一行；DSH 的 ACP 会话列表在任何环境下都会列出它。现在任务 Agent 的会话带有 DSH 给自身子代理的来源标记（origin），两个列表都不再显示它；任务照常运行和回报。较早版本留下的行会一直保留，可以用**归档会话**归档。
- **在 DSH 0.2.1 的桌面版中从 0.5.30 及更早版本更新**（#437，issue #433 与 #436）。在这些版本上，检查版本 → 更新会停在 `already-installed`，而命令行不管理桌面版的 profile。文档现在给出方法：在插件页卸载 dsh-mnemon，再通过**添加插件**以 `dsh-mnemon@<版本>` 重新安装，然后重启应用。记忆数据与设置都会保留。
- **README。** 中英文 README 以 Star 历史与许可证章节收尾（#439、#440）。
- **面向插件作者。** 读取会话日志的插件现在会看到 `origin: "subagent"`、没有父会话的任务 Agent 会话；工作流参考的[委派的子会话](../reference/workflows.md#委派的子会话)一节对此有说明。

## 升级与兼容性

**DSH 0.2.0-rc.2、0.2.1-rc.1 与 0.2.1-rc.2：** 使用**记忆系统 → 状态 → 检查版本 → 更新**，完成后重启 DSH。dsh-mnemon 0.5.31 及更高版本在所有受支持的 DSH 上都可以这样更新；在 DSH 0.2.0-rc.2 上，网页从 0.5.19 起、桌面版从 0.5.22 起也可以。更早的安装，包括 DSH 0.2.1 上会停在 `already-installed` 的 0.5.30 及更早版本，需要手动更新一次：请退出 DSH，安装精确版本，再启动 DSH。

```sh
dsh plugin --profile web add dsh-mnemon@0.5.33
```

写明版本，可以避免 pnpm 在新版本发布后的 24 小时内选用较早的版本。命令行不管理桌面版的 `desktop` profile：在桌面版中，请在插件页**卸载** dsh-mnemon，再通过**添加插件**以 `dsh-mnemon@0.5.33` 重新安装，然后完全退出并重新打开应用。记忆数据与设置都会保留。

**支持的 DSH 版本**不变：DSH 0.2.0-rc.2 与 0.2.1-rc.1，以及此后的 0.2.0 与更高的 0.2 版本（`>=0.2.0-rc.2 <0.2.1-0 || >=0.2.1-rc.1 <0.3.0-0`），其中包括 0.2.1-rc.2，它现在是 npm 的 `latest` 与 `next`。DSH 0.1.7、0.2.0-rc.1 与 0.2.1 的 alpha 版本会拒绝安装本版本，在这些版本上该怎么做见[兼容性与升级](../reference/compatibility.md#更早的-dsh)。

**写明用户名的 Git 同步地址**是本版本新增的。较早的 dsh-mnemon 会拒绝已保存的、写明用户名的地址，甚至无法更改或断开它，因此退回较早版本前请先去掉地址中的用户名。

已有记忆与设置无需迁移，已保存的设置键不变。插件的 peer 下限与 Starter 的外部运行时依赖不变。
